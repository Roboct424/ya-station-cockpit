# Как собрать прошивки со своих устройств

## Откуда вообще берётся версия

Устройство само спрашивает облако (`/check_updates`). В ответе — версия,
`downloadUrl`, `crc32`, `updateId`. Мы этот ответ сохраняем в манифест.

Так была обнаружена `.46`: колонка сама попросила обновление, в ответе был
официальный CDN-URL и CRC32 1524631406. Архив скачали и сверили — это
вендорский файл, «нашим» был только прокси, который его отдал.

## Процедура

```bash
# 1) поднять перехват и дать устройству сходить за обновлением
#    (DNS/TLS-прокси, см. cockpit tls / dns)

# 2) сохранить ответ check_updates в манифест
#    формат: { "<platform>": { "<version>": { ... } } }

# 3) скачать всё, что есть в манифесте
cockpit ota fetch-all --manifest data/manifests.json \
  --platform yandexmini_2 --store data/ota

# 4) сверить и зафиксировать
cockpit ota verify --db firmware/db.json …
cockpit ota import --platform … --version … --file … --store data/ota
cockpit ota observe --platform … --version … --crc32 … --size … --adb
```

Ссылки персональные и истекают — качать надо сразу после получения ответа.

## Что можно получить с конкретных устройств

| Устройство | Платформа | Что реально доступно |
|---|---|---|
| Mini 2 | `yandexmini_2` | текущая предлагаемая версия (подтверждено: `.46`), далее облако уводит на `.50` |
| Хаб / Saturn | `saturn` | отдельная платформа и ОС; OTA скуднее, набор версий зависит от текущей |
| Lite 2 | `plum` (уточняется) | отдельная платформа; обновлений мало |

Общего «списка всех версий» облако не отдаёт: только то, что предлагается
конкретному устройству сейчас. Старые версии — из сообщества, зеркал или
дампов (с проверкой хеша).

## Торренты

Технически рабочая схема: SHA-256 — идентичность файла, DHT не даёт «выключить»
раздачу. Юридически это всё равно распространение образа вендора, поэтому:

* в репозиторий не кладём ни файлы, ни magnet-ссылки;
* в индексе — только хеши и указатели, решает пользователь;
* клиент принимает файл только при совпадении SHA-256.
