# Что будет, если Яндекс закроет облако

## От чего мы реально зависим

| Возможность | Нужно облако? |
|---|---|
| Сопряжение с Wi-Fi звуком | **нет**, совсем |
| Локальная регистрация (свой uid) | **нет** |
| Перехват DNS/TLS и локальный конфиг | **нет** |
| Получение ADB через `get_sync_info` | нужен **один раз** архив прошивки |
| Проверка новых версий | да, но только для получения файлов |

То есть единственная точка отказа — **получение архива прошивки**, а не работа
устройства.

## Политика «взяли один раз — храним вечно»

```bash
cockpit ota import --platform yandexmini_2 --version 0.369.1.46... \
  --file /путь/к/архиву.zip --db firmware/db.json --store data/ota
```

* если версия есть в базе — сверяются размер, CRC32 и SHA-256;
* если нет — хеши считаются и сохраняются локально (`data/ota/<platform>/<version>.json`);
* дальше файл применяется офлайн, без обращения к облаку.

`--db` не обязателен: без него импорт просто фиксирует провенанс.

## Если облако изменит выдачу

1. Уже сохранённые архивы продолжают работать — они у нас.
2. Новые версии можно принимать из любого источника, если совпал SHA-256
   (база — это контракт, а не ссылка).
3. Если старых версий нигде нет — остаётся версионно-независимый путь:
   звук + локальная регистрация, без ADB.

## Честный жёсткий случай

Колонка пришла с прошивкой новее всех доступных архивов, и нужной версии нет
ни у облака, ни в сообществе. Тогда ADB-путь может быть недоступен. Что помогает:

* искать устройство с более старой прошивкой (склад, б/у);
* дамп системного раздела с другого устройства той же платформы + сверка хешей;
* использовать локальные возможности без ADB.

## Правовая рамка

Прошивки — контент вендора. В репозитории только хеши и метаданные; файлы
хранятся локально у пользователя и не распространяются.
