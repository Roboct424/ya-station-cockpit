# Mini 2 (YNDX-00020): обновление и разблокировка рядом с Mini 3

Mini 2 в аккаунте, но ADB закрыт. Заводская `.17` ADB не открывает;
нужна `.46` (`0.369.1.46.4778262943.20261013.299`), файл лежит в
`data/ota/yandexmini_2/` и `firmware/`.

## Селективный hub

Обычный `hub serve` перехватывает всю точку доступа и ломает официальный
аккаунт Mini 3. Поэтому:

```
cockpit hub serve --mode sync --online --only 192.168.137.20
```

* `.20` (Mini 2) получает наш DNS/quasar, `/check_updates` и `.46`;
* `.18` (Mini 3) и остальные идут в настоящий Яндекс;
* `oauth/login/passport`, музыка и Alice у Mini 2 идут напрямую, чтобы
  не подменить официальный токен.

## Порядок

1. В панели 1.6.25 выбрать «Локальный hub только для выбранной станции»,
   цель — Mini 2, включить «Разрешить обновление».
2. «Применить»: hub отдаёт Mini 2 `.46`, станция обновляется и
   перезагружается.
3. После перезагрузки hub отдаёт `/get_sync_info` → открывается ADB.
4. Подключиться `adb connect 192.168.137.20:5555`, проверить версию и
   `launch.json`.
5. Приватность и ADB-маркеры — отдельным шагом после открытия ADB.

## Ограничения

* cert Mini 2 должен доверять нашей цепочке (factory обычно доверяет AAA);
* Mini 2 должна остаться в сети `.20`; если IP сменится — выбрать новый;
* после обновления проверить, что официальный аккаунт/Alice живы; если
  токен всё же сбросился, привязать заново в приложении.

## Почему локальный OTA не пошёл на `.17`

Селективный hub работает: Mini 2 получает DNS `192.168.137.1`, HTTP 204,
`/check_updates`; но TLS обрывается:

```
quasar: рукопожатие с 192.168.137.20 не удалось:
received fatal alert: UnknownCA
```

Заводская `.17` не доверяет `eMudhra → AAA` и локальному CA. Установить
корень без ADB нельзя. Варианты: USB ADB, звуковой код активации ADB,
либо официальное обновление через приложение/реальный CDN. После
появления ADB — наш CA, приватность, маркеры.
