# База прошивок

Файлы прошивок по ~68 МБ в git не кладём. В репозитории — **база хешей**:
`firmware/db.json`. Любой архив принимается только если совпал размер,
CRC32 и SHA-256.

## Запись

```json
{
  "platform": "yandexmini_2",
  "version": "0.369.1.46.4778262943.20261013.299",
  "size": 67796480,
  "crc32": 1524631406,
  "sha256": "192aa984...",
  "adb": true,
  "notes": "Рабочая точка для сетевого ADB; .50 отвергает цепочку"
}
```

`adb: true` — версия проверена как рабочая для локального получения ADB
(через `get_sync_info`).

## Команды

```bash
cockpit ota db --db firmware/db.json            # список
cockpit ota db --db firmware/db.json --platform yandexmini_2
cockpit ota verify --db firmware/db.json \
  --platform yandexmini_2 --version 0.369.1.46... --file путь/к/архиву.zip
```

## Как пополнять

1. Снять `check_updates` с конкретной колонки (официальный источник).
2. Скачать архив, посчитать CRC32 и SHA-256.
3. Добавить запись с пометкой, проверен ли ADB.
4. Файл хранить локально (`data/ota/...`), в git — только запись.

## Почему так

Хеш — это контракт: если у кого-то файл с тем же SHA-256, это ровно тот же
архив, откуда бы он ни взялся. Это позволяет принимать зеркала и архивы
сообщества, не доверяя источнику на слово.
