# Дневник разработки

Здесь фиксируются решения, ошибки и их причины — чтобы через месяц не гадать,
почему сделано именно так. Формат: дата, что сделано, что сломалось, как починили.

---

## 2026-11-18 · Фаза 0: фундамент

### Задача

Начать новый проект на Rust: приложение для локальной настройки и обслуживания
Яндекс Станций (мастер + консоль), с журналом каждого шага, проверками и откатом.
Пока без сети и перехвата — только скелет, который не стыдно развивать.

### Принятые решения

1. **Workspace из четырёх крейтов** (`core`, `config`, `doctor`, `cli`).
   Причина: ядро не должно зависеть от CLI и от платформы; позже появится
   `api` (локальный HTTP) и `app` (Tauri), и они подключатся к тому же ядру.

2. **Журнал — JSON Lines, а не SQLite.**
   Причины: нет нативной зависимости; каждая строка сбрасывается на диск, поэтому
   падение процесса не теряет историю; файл читается `grep`/`jq` без нашего кода.
   Когда понадобятся индексы и запросы — подменим реализацию `Journal`,
   не меняя вызывающий код. Трейт уже отделён.

3. **Шаг = транзакция.** Контракт `Step`:
   `is_done` (предусловие) → `run` (действие) → `verify` (доказательство) →
   `rollback` (компенсация). Это ядро «банковского» поведения: нельзя «сделать
   и надеяться».

4. **Упавший шаг не откатывается.** Откатываются только успешно завершённые
   шаги, в обратном порядке. Упавший шаг либо не изменил состояние, либо
   оставил его частично — для таких случаев позже добавим `recover`.
   Это зафиксировано тестом `runner_rolls_back_only_executed_steps`,
   чтобы не «починить» случайно.

5. **Ошибка = код + подсказка.** `CockpitError::code()` и `hint()` дают UI и
   журналу машиночитаемый код (`run.step_failed`) и человеческое «что делать».
   Позже к этому добавится таблица «код → причина → лечение» в `doctor`.

6. **Конфиг валидируется целиком.** `Config::validate()` возвращает список
   проблем, а не первую. Причина: пользователю нужно видеть все ошибки сразу.

### Что реализовано

- `cockpit-core`: `Record` (события), `JsonlJournal`, `Step`, `Runner`,
  `CockpitError`, `Context`.
- `cockpit-config`: TOML-конфиг с умолчаниями, `deny_unknown_fields`
  (опечатка в ключе = ошибка, а не тихий игнор), валидация, шаблон `cockpit.toml`.
- `cockpit-doctor`: 8 проб (платформа, права, конфиг, каталог, журнал, DNS-порт,
  HTTP-порты, поддержка перехвата) с подсказками.
- `cockpit-cli`: `doctor`, `config init|check|show`, `journal tail|stats`,
  `run selfcheck`, `version`.
- Тесты: 4 на движок (журнал, успех, откат, dry-run) + 7 на конфиг.

### Ошибки и как чинили

| Что | Причина | Решение |
|---|---|---|
| `clippy: should_implement_trait` на `Runner::add` | имя `add` намекает на `std::ops::Add` | переименовали в `with_step` / `with_steps` |
| `clippy: derivable_impls` для `Config` | ручной `Default`, хотя все поля дефолтные | `#[derive(Default)]`, ручные `Default` остались у секций |
| тест ссылался на несуществующий вариант `Record::StartStepMarker` | писал тест «по памяти» | тест переписан на подсчёт `kind()` |
| первая версия теста отката проверяла не тот шаг | семантика: упавший шаг не откатывается | тест проверяет флаг **первого** шага и отсутствие отката у упавшего |

### Известные шероховатости (осознанно отложены)

1. **`doctor` создаёт `data/`** — проба записи. Формально диагностика «меняет»
   систему. Позже: проверять запись во временном каталоге, а `data/` не трогать.
2. **`Context` не содержит конфиг** — шагам он пока не нужен; появится вместе
   с сетевыми шагами, чтобы не тащить зависимость ядра на `cockpit-config`.
3. **Нет отмены по Ctrl+C** — журнал уже append-only, добавим обработчик сигнала
   и статус `run.cancelled`.
4. **Нет `recover` для частично применённых шагов** — появится, когда будут
   реальные действия (файлы, правила firewall), а не маркер.

### Как отлаживать (шпаргалка)

```bash
cargo run -- doctor                 # состояние окружения
cargo run -- doctor --json          # машинный отчёт
cargo run -- run selfcheck          # проверка движка и журнала
cargo run -- journal tail -n 50     # что происходило
cargo run -- journal stats          # сколько запусков/провалов
RUST_LOG=debug cargo run -- doctor  # подробный лог (stderr)
```

Журнал: `data/journal.jsonl`, одна строка = одно событие.
Поля: `kind`, `ts`, `run_id`, для шагов — `step`, `ok`, `detail`, `duration_ms`.
