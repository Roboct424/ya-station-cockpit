# Журнал болячек инструментов

Здесь фиксируем особенности библиотек и системных API, на которые мы уже
наступили или можем наступить. Цель — не собирать «интересное», а **не
наступать дважды** и оставлять предупреждение ровно в том месте кода, где
болячка проявляется.

## Как пополнять

1. При добавлении зависимости прогоняем три сценария:
   * **пусто** — нет файла, пустой список, `None`;
   * **битые данные** — обрезанная строка, чужой формат, CRLF;
   * **повтор** — второй вызов, повторная инициализация, гонка.
2. Если поведение неочевидно — заводим запись здесь.
3. В коде ставим комментарий `// GOTCHA: G-00X` рядом с местом, где это важно.
4. Если можно починить локально — чиним и отмечаем `исправлено` + тест.
5. Если это ограничение внешнего API — отмечаем `принято` и пишем, что делать.

Статусы: `исправлено` · `принято` · `под наблюдением`.

## G-001 · clap: `default_value` скрывает явный ввод

* **Крейт:** `clap` 4.x (derive)
* **Симптом:** `--config /опечатка.toml` молча игнорируется — программа берёт
  `cockpit.toml` по умолчанию. Пользователь думает, что применился его файл.
* **Причина:** при `default_value` поле всегда заполнено, и отличить «не указал»
  от «указал ровно дефолт» невозможно.
* **Решение:** поле `Option<PathBuf>` без `default_value`; функция
  `resolve_config_path` подставляет умолчание только если аргумент не задан,
  а явно указанный путь обязана существовать.
* **Где:** `crates/cli/src/main.rs` (`resolve_config_path`)
* **Статус:** исправлено

## G-002 · JSONL: одна битая строка ломала весь журнал

* **Крейт:** `serde_json` + наш `JsonlJournal`
* **Симптом:** после обрыва записи (питание, kill -9, ручная правка) `journal tail`
  падал целиком: «строка 42: expected value».
* **Причина:** строгий разбор всего файла без изоляции ошибок на строку.
* **Решение:** `read_all` возвращает `JournalRead { records, skipped }`;
  битые строки пропускаются и показываются предупреждением, история читается.
* **Где:** `crates/core/src/journal.rs`, `JournalRead`
* **Тест:** `corrupt_line_does_not_hide_history`
* **Статус:** исправлено

## G-003 · serde: `deny_unknown_fields` несовместим с `flatten`

* **Крейт:** `serde` 1.x
* **Симптом:** если добавить в конфиг вложенную секцию через `#[serde(flatten)]`,
  сборка падает: `deny_unknown_fields` и `flatten` взаимоисключающие.
* **Причина:** `flatten` собирает «остаток» полей, а `deny_unknown_fields`
  требует, чтобы неизвестных полей не было.
* **Решение:** не использовать `flatten` в конфиге. Если понадобится —
  отказаться от `deny_unknown_fields` и валидировать ключи вручную.
* **Где:** `crates/config/src/lib.rs` (комментарий у `Config`)
* **Статус:** принято

## G-004 · toml: `None` не сериализуется — ключ исчезает

* **Крейт:** `toml` 0.8
* **Симптом:** `cockpit config show` не печатает `journal`, хотя поле есть
  в структуре. Кажется, что настройка потерялась.
* **Причина:** `Option::None` не имеет представления в TOML и опускается.
* **Решение:** это нормально и даже полезно (конфиг короче). Но помнить:
  «нет ключа» и «None» в TOML неразличимы — не строить на этом логику.
* **Где:** `crates/config/src/lib.rs` (`paths.journal`)
* **Статус:** принято

## G-005 · chrono: `timestamp_millis()` не уникален

* **Крейт:** `chrono` 0.4
* **Симптом:** два запуска в одну миллисекунду получают одинаковый `run_id`,
  записи в журнале склеиваются при анализе.
* **Причина:** время — не идентификатор.
* **Решение:** `run_id = millis-micros-seq`, где `seq` — атомарный счётчик
  процесса (`AtomicU64`). Гарантирует уникальность в рамках процесса.
* **Где:** `crates/core/src/run.rs` (`new_run_id`)
* **Статус:** исправлено

## G-006 · tracing: повторная инициализация возвращает ошибку

* **Крейт:** `tracing-subscriber` 0.3
* **Симптом:** второй `try_init()` (например, в тестах или при повторном входе
  в `dispatch`) возвращает `Err`, и логи молча пропадают.
* **Причина:** глобальный подписчик можно установить только один раз.
* **Решение:** результат `try_init()` сознательно игнорируется; логирование
  считается опциональным. Если понадобится несколько подписчиков — использовать
  `tracing::subscriber::with_default` в тестах.
* **Где:** `crates/cli/src/main.rs` (`init_logging`)
* **Статус:** принято

## G-007 · Windows/PowerShell: кодировка аргументов и stdout

* **Инструмент:** PowerShell 5.1 + Windows-консоль (не Rust-библиотека)
* **Симптом:** русский текст в JSON/HTTP-теле, отправленном из PowerShell,
  приходит как `?????`; вывод программ в консоли выглядит как `������`.
* **Причина:** консоль работает в cp866/cp1251, а данные должны быть UTF-8;
  `Invoke-RestMethod` перекодирует тело.
* **Решение:** для API — писать JSON в файл в UTF-8 и отправлять `curl --data-binary @file`;
  для чтения вывода — не доверять консоли, проверять файлы через Python.
* **Где:** скрипты сборки/публикации (вне Rust-кода)
* **Статус:** принято

## G-008 · BufRead::lines: молча съедает `\r`

* **Крейт:** `std`
* **Симптом:** журнал, отредактированный в Windows-редакторе (CRLF), читается
  нормально — и это неочевидно, если рассчитывать на точное сравнение строк.
* **Причина:** `lines()` отрезает `\n` и завершающий `\r`.
* **Решение:** помнить при разборе бинарных/точных форматов: для JSONL это благо,
  для сравнения байт — использовать `read_until`.
* **Где:** `crates/core/src/journal.rs`
* **Статус:** принято

## G-009 · arc-swap: подменять только после валидации

* **Крейт:** `arc-swap` 1.x
* **Симптом:** если записать в `ArcSwap` конфиг сразу после парсинга, одна
  опечатка в файле «на лету» ломает работающий процесс: старые настройки уже
  потеряны, новые невалидны.
* **Причина:** `store()` не знает про бизнес-правила.
* **Решение:** `LiveConfig::reload` сначала парсит и валидирует, и только потом
  делает `store`. При ошибке возвращает `Err`, старый конфиг остаётся.
* **Где:** `crates/config/src/lib.rs`, `LiveConfig::reload`
* **Статус:** исправлено

## G-010 · notify: несколько событий на одно сохранение

* **Крейт:** `notify` 8.x
* **Симптом:** редактор сохраняет файл через временный файл + rename, и приходит
  пачка событий (`Modify`, `Rename`, `Create`). Без дебаунса конфиг
  перечитывается 3–5 раз, а в журнале появляется мусор.
* **Причина:** файловые события описывают операции, а не «сохранение».
* **Решение:** на каждое событие ждём 200 мс и перечитываем один раз; сравнение
  `to_toml()` отсекает ложные срабатывания, когда содержимое не изменилось.
* **Где:** `crates/config/src/lib.rs` (`watch`), `crates/cli/src/main.rs`
* **Статус:** принято

## G-011 · Своё: постусловие нельзя использовать как предусловие

* **Крейт:** наш `ScenarioStep`
* **Симптом:** шаг с проверкой `file_absent` пропускался ещё до выполнения:
  `is_done` считал, что «раз файла нет — всё уже сделано». Проверка результата
  подменяла проверку необходимости.
* **Причина:** одна и та же проверка использовалась в двух ролях.
* **Решение:** добавлено отдельное поле `skip_if`; `check` — только постусловие.
  По умолчанию шаг выполняется всегда (операции идемпотентны).
* **Где:** `crates/scenarios/src/lib.rs` (`is_done`)
* **Тест:** `failed_check_rolls_back_previous_steps`, `skip_if_prevents_execution`
* **Статус:** исправлено

## G-012 · BOM в начале файла ломает YAML и TOML

* **Крейты:** `serde_yaml` 0.9, `toml` 0.8
* **Симптом:** файл, сохранённый в PowerShell (`Set-Content -Encoding utf8`)
  или в Блокноте, не читается: `missing field 'title' at line 1 column 2`.
* **Причина:** UTF-8 BOM (`EF BB BF`) остаётся первым символом и парсер
  воспринимает его как часть ключа.
* **Решение:** снимаем BOM перед разбором в `Scenario::parse` и `Config::load`.
* **Где:** `crates/scenarios/src/lib.rs`, `crates/config/src/lib.rs`
* **Тест:** `tolerates_bom`
* **Статус:** исправлено

## G-013 · serde_yaml: библиотека в режиме поддержки

* **Крейт:** `serde_yaml` 0.9
* **Симптом:** крейт помечен deprecated (архивирован автором), новые версии не
  выходят.
* **Причина:** автор прекратил поддержку; форки (`serde_yaml_ng`, `serde_norway`)
  продолжают развитие.
* **Решение:** пока оставляем 0.9 — API стабилен, безопасность не критична
  (парсим локальные файлы). При следующем крупном обновлении мигрируем на
  поддерживаемый форк; весь доступ к YAML — в одном файле.
* **Где:** `crates/scenarios/src/lib.rs`
* **Статус:** под наблюдением

## G-014 · Таймаут не убивает поток

* **Инструмент:** `std::thread` (наш `Runner`)
* **Симптом:** шаг с `timeout_ms` возвращает `run.timeout`, но операция
  продолжает выполняться в фоне и может дописать файл уже «после провала».
* **Причина:** в Rust нельзя безопасно прервать поток; `JoinHandle` при таймауте
  отсоединяется.
* **Решение:** шаг обязан быть идемпотентным, а долгие операции — проверять
  контекст/токен отмены (появится в фазе 3). В журнале фиксируется таймаут,
  откат выполняется только для завершённых шагов.
* **Где:** `crates/core/src/run.rs` (`execute`)
* **Тест:** `timeout_returns_without_waiting_for_step`
* **Статус:** принято (осознанное ограничение)

## G-015 · netsh portproxy не умеет UDP

* **Инструмент:** Windows `netsh interface portproxy`
* **Симптом:** перенаправление DNS (UDP/53) через portproxy невозможно.
* **Причина:** portproxy поддерживает только TCP (`v4tov4`).
* **Решение:** `WindowsAdapter::redirect_udp` возвращает `NetError::Unsupported`
  с кодом `net.unsupported`; для UDP на Windows понадобится WinDivert/WFP.
  На Linux `iptables -p udp` работает.
* **Где:** `crates/net/src/lib.rs`
* **Тест:** `udp_redirect_depends_on_platform`
* **Статус:** принято

## G-016 · DNS-ответ игнорирует EDNS/OPT

* **Инструмент:** наш `cockpit-intercept`
* **Симптом:** в ответе `arcount = 0`, даже если клиент прислал OPT-запись
  (EDNS0). Часть резолверов это принимает, но размер ответа ограничен 512 байт.
* **Причина:** мы копируем только вопрос, отбрасывая additional-секцию.
* **Решение:** для A/AAAA этого достаточно; при переходе на DoH/большие ответы
  заменить парсер на `hickory-proto`.
* **Где:** `crates/intercept/src/lib.rs` (`handle_query`)
* **Статус:** под наблюдением
