# Локальный ADB: что уже есть и чего не хватает

## Что умеет программа сейчас

* `cockpit device info --addr 192.168.137.113:5555` — подключение по сети,
  список устройств, версия ядра, root/не root.
* `cockpit device list` — что видит adb.

Транспорт абстрагирован (`CommandRunner`), поэтому тесты идут на заглушках,
а не на живом устройстве.

## Локальный OTA/sync (готово)

```bash
cockpit local-ota --bind 127.0.0.1:18443 --ca-out data/ca.pem \
  --manifest data/manifests.json --platform yandexmini_2 \
  --version 0.369.1.46... --firmware путь/к/архиву.zip
```

Отдаёт по HTTPS:

* `/check_updates` — версия, CRC32, `downloadUrl` на наш же сервер;
* `/get_sync_info` — конфиг с `adbd.network = true`;
* `/firmware/<файл>` — сам архив, с поддержкой Range (206).

Проверено вживую: ответы корректны, архив отдаётся по частям.

## Сценарий активации (готов)

```bash
cockpit activate --addr 192.168.137.113:5555 \
  --manifest data/manifests.json --platform yandexmini_2 \
  --version 0.369.1.46... --firmware путь/к/архиву.zip
```

Шаги (каждый с проверкой и записью в журнал):

1. `verify-firmware` — CRC32 архива совпадает с манифестом;
2. `wait-adb` — `adb connect` + появление в `adb devices`;
3. `check-root` — `id -u == 0`;
4. `read-version` — версия ядра для журнала.

При провале — `run_finished ok=false` и подсказка. Откат у этих шагов
отсутствует осознанно: они ничего не меняют в системе.

## Одна команда: активация + закрепление

```bash
cockpit activate --addr 192.168.137.113:5555 \
  --manifest data/manifests.json --platform yandexmini_2 \
  --version 0.369.1.46... --firmware путь/к/архиву.zip \
  --serve-ota --ca-out data/ca.pem \
  --guard firmware/S99adbguard
```

Что происходит:

1. поднимается локальный OTA/sync (`--serve-ota`) и живёт до конца сценария;
2. проверяется CRC архива;
3. ожидается ADB, проверяется root и читается версия;
4. `install-guard`: если сторож уже есть — бэкап в `.bak`, затем `adb push`,
   `chmod 755` и проверка `-x`; при провале откат возвращает `.bak`
   или удаляет файл.

## Чего ещё нет

* GUI: пока только CLI.
* `install-guard` покрыт автотестом на последовательность команд
  (бэкап → push → chmod → проверка → откат), но не на живом ADB.
* Бэкап существующего сторожа делается в `<path>.bak`; откат возвращает его
  через `mv -f`.

## Рабочая последовательность (проверена вручную)

1. Устройство в состоянии, где принимает наш TLS (сброс/первый запуск).
2. Наш прокси отвечает на `check_updates` нужной версией (архив из `data/ota`).
3. Колонка скачивает и применяет прошивку.
4. `get_sync_info` отдаёт конфиг с `adbd.network` → сетевой ADB.
5. `adb connect`, `id -u` = 0, закрепление через init-скрипт.

## Ограничения

* `.50` и новее могут отвергать цепочку — проверять на каждой сборке.
* Без совместимой прошивки шаг 2 не пройдёт.
* Всё это делается только на своих устройствах.
